# v0.8.1：攻击强制停步

接续 v0.8 的完整主角动作与体型调整。本轮统一攻击规则：攻击时立即停止移动，直到动作收招结束，不能漂移攻击。

## 当前行为

- 普通拳、三连拳、重拳、终结技、冲刺接招、抓取、痛殴、投掷与暴怒发动均锁定横向和纵向移动。
- 双击方向的普通冲刺仍然可用；冲刺中按 J/K，立即停在起手位置，分别打出急停冲刺拳或肩撞。伤害、有效范围、敌人击退与倒地效果沿用原参数。
- 起手后朝向固定；按住反方向、斜方向或在攻击期间双击方向，都不会滑步、转身或打断攻击去冲刺。
- J-J-J / J-J-K 的缓存连招先于移动输入处理，中间不会漏出一个行走帧。最后一拳收招完毕后，按住方向即可继续移动，无需松开再按。
- 攻击期间的方向键双击不会计入下一次冲刺；收招后需要两次新的方向按下才触发冲刺。
- 受击会先取消攻击，再正常硬直或击退；投掷只让敌人飞出，碧保持原地。

## 实现要点

- `src/main.js` 的 `stopPlayerMovement()` 清零速度与加速度，并同步物理身体的位置和前帧位置。Phaser 在场景更新前已计算本帧移动，单独 `setVelocity(0, 0)` 仍会在 `postUpdate` 残留一帧位移。
- 所有动作共用这一停步入口，冲刺攻击不再带 `speed` / `travel` 位移参数。
- 场景更新先结算当前动作，再处理攻击输入和缓存，最后处理移动。缓存从动作结束时起额外保留 140ms，避免最早允许输入的一帧因时间步越界而丢失。
- 攻击起手清空旧冲刺与方向双击记录；攻击期间不采集新的双击记录。

## 验证

`npm test`：50 项通过。覆盖原有敌人、盾牌、抓取、投掷、受击、波次与重开逻辑，并新增攻击停步、连招帧顺序和方向双击回归检查。

其中直接使用项目依赖的 Phaser Arcade Body / World 物理实现，在 30、60、144fps、左右两种朝向下，逐帧检查全部七种攻击：起手前预置移动速度，模拟物理先更新、场景再更新、物理最后同步精灵的顺序，确认攻击全程位置不变且收招后可移动。另验证受击取消攻击后仍正常击退。这些测试不包含浏览器渲染。

`npm run build` 与 `git diff --check` 通过。游戏和动作预览页均成功构建。

浏览器验收未完成：本轮云浏览器访问本地地址返回 `ERR_BLOCKED_BY_CLIENT`，本地 Chromium 下载超时。下列手动项目留作 Codespaces / 本机手感验收。

## 试玩清单

1. 按住 D 或 D+S 行走，点 J/K：起手停步，攻击全过程不改变站位，收招后继续行走。
2. 双击左/右冲刺后按 J/K：出招立即刹停，前摇、命中和收招均不向前滑。
3. 出第一拳后按住反方向，在每拳收招前接 J-J-J / J-J-K：连续攻击保持起手朝向，整套结束后才按方向移动。
4. 攻击期间快速双击反方向：不能触发冲刺；结束后单按一次也不会冲刺。
5. 抓住敌人后按住方向并按 J/K：痛殴或投掷时站定，投出的敌人仍正常飞出。
6. 在出拳前摇被敌人命中：攻击取消，受击击退正常；死亡后按 R 重开，移动和攻击可继续使用。

运行 `npm run dev` 打开游戏；同地址的 `/animations.html` 可检查 22 组动作。
